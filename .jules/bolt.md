## 2024-05-24 - [Avoid Promise.all for Independent State Updates]
**Learning:** In React components, wrapping independent, non-awaited `fetch` calls in `Promise.all` or `Promise.allSettled` to update independent state variables is actually a performance anti-pattern. While it looks like it "batches" network requests, the original un-awaited `fetch` calls were already executing concurrently. `Promise.all` forces React to wait for the *slowest* request before updating *any* state, degrading perceived performance and Time-to-Interactive for the faster components.
**Action:** Do not group independent `fetch` calls in `Promise.all` if they update separate pieces of state. Only use `Promise.all` when the resulting data is codependent or when fetching in a server component/SSR context where you must await all data before rendering.

## 2024-05-24 - [Optimize Derived State in Render Body]
**Learning:** In complex dashboard components, doing heavy data grouping (like `.reduce` to create `chapters`), filtering, and nested conditionals on every render cycle blocks the main thread. By wrapping these in a top-level `useMemo` block, the app skips these heavy iterations on minor state changes (like UI toggles), noticeably improving render speeds on large datasets. Care must be taken to ensure the `useMemo` sits above any conditional early returns to obey React hook rules.
**Action:** Identify expensive data manipulations (grouping, filtering) in render bodies of data-heavy components and extract them using `useMemo`.
