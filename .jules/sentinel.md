## 2024-05-11 - [CRITICAL] Prevent XSS via dangerouslySetInnerHTML in Lesson Rendering
**Vulnerability:** Found a Cross-Site Scripting (XSS) vulnerability in `app/dashboard/course/learn/page.tsx` where user-submitted or unverified course text content (`activeLesson.text_content`) was being rendered directly using React's `dangerouslySetInnerHTML` without any sanitization.
**Learning:** In a Next.js (SSR/Client) environment, directly injecting HTML is risky. The lack of sanitization before `dangerouslySetInnerHTML` allows any scripts embedded in the text content to execute. Furthermore, using standard `dompurify` can cause hydration mismatch errors or fail on the server since it relies on the `window` object.
**Prevention:** Always sanitize any dynamic or user-generated HTML content before rendering it. In this project, `isomorphic-dompurify` should be used instead of standard `dompurify` to safely sanitize HTML on both the server and the client to avoid SSR issues. The solution involves wrapping the content with `DOMPurify.sanitize()`.
