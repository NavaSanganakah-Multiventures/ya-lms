## 2025-02-24 - [Auth Bypass using User-Agent Spoofing]
**Vulnerability:** The App Signature verification logic in `src/index.ts` allowed requests to sensitive OTP endpoints (`/api/auth/send-otp` and `/api/auth/verify-otp`) without an App-JWT if the `User-Agent` matched specific strings (`AdityanveshanApp/1.0` or `AdityanveshanAdmin/1.0`).
**Learning:** `User-Agent` strings are easily manipulated by attackers and should never be used as a standalone factor to bypass cryptographic signature or token verification checks on sensitive API routes.
**Prevention:** Strictly enforce cryptographic verification (like App-JWT validation) or session-based authentication for critical endpoints, ensuring fallback paths don't introduce trivial bypass mechanisms based on insecure client-provided headers.
## 2024-07-10 - [Removed SELECT * Queries for Database Security]
**Vulnerability:** Several high-frequency queries (e.g., in `handleGetProfile`, `createRazorpaySubscription`) were using `SELECT * FROM Users`, loading all columns (including previously removed sensitive fields like `password_hash` and `salt`) into memory. Some functions then explicitly deleted these fields before returning them.
**Learning:** This approach fails secure-by-default principles because any newly added sensitive column to the `Users` table would automatically be exposed unless the developer manually added another `delete` statement. In Cloudflare D1 and serverless environments, it also wastes memory and bandwidth.
**Prevention:** Always explicitly define the required columns in the `SELECT` statement rather than fetching all and filtering afterwards (e.g., `SELECT id, email, full_name ... FROM Users WHERE ...`).
